A week with Cairn takes three short rituals.

No sprint planning poker, no status meeting. The tool keeps the state, so the team only meets when something is actually stuck.

  1. Monday

    Triage the inbox in ten minutes

    New bugs from Sentry, support and teammates land in one inbox. Each one gets a single keystroke: accept it into the cycle, park it in the backlog, or close it with a reason the reporter can read.

    1 Accept into Cycle 31

    2 Move to backlog

    3 Close as duplicate

    4 Close as won't fix

  2. Wednesday

    See what's stuck without asking

    The cycle view plots open issues against the days left. Anything nobody has touched in three working days gets flagged in the list, so the standup is about that one issue instead of everyone's.

  3. Friday

    Post the changelog you already wrote

    Issues closed this cycle roll up into a draft release note, grouped by project. Edit the wording, then post it to a Slack channel or copy it as Markdown into your docs.

    Platform, week of Oct 19

    • Webhook retries no longer double-charge when Stripe times out CRN-214
    • Password reset emails are rate limited per account CRN-196
    • Staging runs Postgres 16 CRN-198

Close issues from the commit you were writing anyway.

Connect GitHub or GitLab once. Mention an issue ID in a branch name and Cairn moves it to In progress. Write Fixes CRN-214 in a commit and the issue closes when the pull request merges into main.

Nobody has to remember to drag a card on Friday afternoon.

$ git commit -m "Retry webhooks with idempotency keys" \
    -m "Fixes CRN-214"

What we left out, on purpose.

  • Story points

    Issues are small, medium or large. Small teams estimate better in conversation than in Fibonacci.

  • A workflow builder

    Every team gets the same five statuses. You can rename them; you can't build a 14-step approval chain.

  • Gantt charts and roadmaps

    Cairn plans one cycle ahead. For the quarter, a shared doc does the job better.

  • Admin tiers

    Everyone on the team can do everything, and every change is in the issue history.
